# Advanced native analysis and investigation

The user authorizes implementation of the full roadmap described in the comparison: decompilation, deeper analysis, symbols, scale, automation, debugger, emulation, patching, binary comparison and extensions. C++20 remains the primary language; Ghidra is inspiration only. The earlier prohibition on compilation, configuration, tests, product execution and dependency installation remains in force. Delivery is source, not proof of industrial parity.

## Subsystems and contracts

1. **Decompiler:** `decompiler.hpp`, `decompiler*.cpp`. `decompile_function(const AnalysisSnapshot&, qsizetype function_index, const DecompilationOptions& = {}, std::stop_token = {}) -> DecompilationResult`. Result fields `pseudocode`, `ssa_text`, `warnings`, `modeled_instructions`, `total_instructions`, `complete`. Structured, typed operations, SSA/dataflow, conservative value propagation and readable control flow must retain instruction addresses; unsupported effects invalidate affected state and remain explicit. No guessed source/type/ABI is presented as fact. Start with scalar x86/x64, retain fallback for other architectures. Bounded work/output and cancellation throughout.
2. **Binary enrichment and symbols:** `enrichment.hpp`, `enrichment.cpp`, `debug_symbols.cpp`. `enrich_binary(shared_ptr<BinaryFile>, const BinaryMetadata&, std::stop_token = {}) -> BinaryEnrichment`; fields `symbols`, `entries`, `imports`, `references`, `warnings`, `details` (QJsonObject). Own parsing of PE exception/function metadata, CodeView/PDB identity, TLS callbacks where recoverable, ELF relocation/import slots and available debug metadata. Explicit local symbol-map import API. Do not claim full PDB/DWARF decoding if only a subset is supported. New seeds must be backed executable bytes; inferred entries carry provenance. No implicit network symbol download or target execution.
3. **Investigation tools:** `investigation.hpp`, `investigation*.cpp`, `debugger*.cpp`, `plugin*.cpp`. Bounded byte/function comparison, original-preserving patch export, a bounded interpreter for explicitly supported instructions, a Windows debugger session with explicit launch/attach, breakpoints, stepping and memory/register inspection, and explicit opt-in extension loading. No debugger, plugin or emulation runs during development. Native APIs are callable through desktop/CLI; unsupported host/instruction capability must return a real error. No success-only stubs.
4. **Integration:** root owns analysis pipeline, an independent headless CLI, desktop actions/views, CMake, project metadata and documents. Enrichment is added before function discovery. Resolved immutable pointers can add code targets; writable/import slots remain unresolved unless justified. Decompiler is available in its own tab and export. Tools become accessible with real input/output paths. CLI commands document structured JSON and errors. Cache keys include input hash, engine/options and function content; cache failures do not masquerade as semantic success.

## Resource and integrity rules

Keep existing analysis ceilings (200000 instructions, 4096/function, 10000 functions, 300s, strings10000, preview4096). New work adds its own explicit caps; no unbounded table reads or recursion. All tools preserve originals, reject exports over protected samples/project internals and use atomic output. Address arithmetic, half-open intervals and fixed-width semantics are checked. Background jobs retain immutable snapshots and stale-result tokens. Source integrity is verified before saved analysis is consumed. Features that need external libraries use already-installed optional dependencies only; no FetchContent/downloads or runtime installation.

## Acceptance status

All dynamic acceptance is deferred by explicit user instruction. Source review checks integration signatures, error paths, conditional compilation, bounds and truthful capability reporting. Future acceptance requires controlled compiler fixtures, malformed files, differential semantic checks, real GUI flows, debugger lifecycle tests and reproducible comparisons with Ghidra on the same corpus and configuration. No benchmark result or superiority claim is fabricated.
